# BUILD PLAN: Headless Verification Harness + Two Live-Bug Fixes

## Part 1 — IMMEDIATE FIXES (serial, do first; caret first)

### FIX-1 (P0): Caret falls below wrapped compose box

**Owner files:** `src/bin/yalda-gpui/yux/list.rs` (helper + test), `src/bin/yalda-gpui/agent.rs` (call site).
**Root cause:** `compute_window` computes the vertical window in *logical lines* but the compose box is now word-wrapped, so 8 logical lines ≠ 8 visual rows; the caret's visual row can fall below the 144px box. Violates INV-UX-1.

**Steps (in order):**
1. `yux/list.rs` — add `compose_first_visible_line_with_wrapping(cursor_line, caret_visual_row_within_line, prev_top_line, visual_rows_per_line: &[usize], visible_visual_rows) -> usize` (pure, signature from diagnosis).
2. `agent.rs:1896` `Compose::compute_window` — build `visual_rows_per_line: Vec<usize>` via `wrap_line_cols(..).len()` per logical line, compute `caret_visual_row_in_line` via `caret_visual_row(...)`, and call the new helper. `visible_rows` now means *visual* rows.
3. `screens.rs:1229` — no code change; the `8` it passes is now correctly interpreted as 8 visual rows.

**Regression test (headless, pure-logic — no infra needed):**
`compose_first_visible_line_with_wrapping_keeps_caret_visual_row_in_window` in `yux/list.rs` `tests` module. Asserts for a known `visual_rows_per_line` shape that the caret's *global visual row* always lands inside `[top_visual_row, top_visual_row + visible)`.

**Note:** This test is logic-level only. The *painted-bounds* version of this guarantee (caret row bounds inside box bounds) requires INFRA-A and lands in TEST-UNIT-1 below. Ship both — the pure test pins the math, the bounds test pins the integration.

### FIX-2 (P1): Markdown breaks across frozen boundary

**Owner file:** `src/bin/yalda-gpui/agent.rs` (single file — no overlap with FIX-1's `agent.rs` region if sequenced; see Sequencing).
**Root cause:** the code-fence loop in `detect_block_ranges` (agent.rs:845–852) omits the `is_frozen` check the table loop (line 867) has, so it emits ranges spanning frozen+unfrozen lines and corrupts rendering.

**Step:** agent.rs:857 — change `if closed && i > start + 1 {` → `if closed && i > start + 1 && is_frozen(i - 1) {`.

**Regression test (headless, pure-logic):**
`detect_block_ranges_respects_frozen_boundary_for_code_fences` in agent.rs `tests` module (or `tests.rs`). Build frozen text with an unclosed ```` ```python ````, append unfrozen lines containing a closing fence; assert `detect_block_ranges` emits no range crossing into unfrozen lines.
