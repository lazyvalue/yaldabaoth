## SketchGpuiView — top-level view shell, chrome, overlay & global state (src/bin/sketch-gpui/main.rs:5836-5907)

_SketchGpuiView is the root GPUI render entity and the single owner of every global/chrome/overlay knob for the whole window. Its 18 fields split into four groups: (1) presentation config that should be a settings/theme owner but is currently raw fields with no persistence (theme, body_font, code_font, text_scale, agent_status_position); (2) ad-hoc modal overlay slots, each a separate Option, that are mutually-exclusive-by-convention but not by type (menu, buffer_switcher, session_switcher, workspace_picker, rename_overlay) plus a transient toast (transient_status) and the startup splash timer (splash_until); (3) the real source-of-truth document/workspace model (workspace, which itself owns tabs, the split tree, and the per-tab rail) and the doc-view interaction state (doc_selection, focus_handle); (4) external/derived plumbing — the session-server handle (session_server), a per-frame caches (viewport_width_px, line_layouts), the shared syntect highlighter, and two build-loop candidate flags (is_candidate, candidate_promote_ready). The dominant drift hazards: the five overlay Options can in principle be Some simultaneously (no single "active modal" invariant), text_scale/theme/fonts/agent_status_position are not persisted so they reset every launch (and theme is never saved despite a Workspace persistence layer existing), and line_layouts is a per-frame Rc<RefCell> scratch map that must be cleared at the top of every doc render or it leaks stale hit-test bounds. The rail is NOT a top-level field — it lives per-tab inside workspace (workspace.rs Tab.rail), so the shell delegates rail ownership entirely to Workspace._

## struct AgentState (src/bin/sketch-gpui/main.rs:4890-5074), with cache machinery at 5076-5149 and reset/reconcile at 5360-5445

_AgentState is the per-session state for an ACP-attached Claude agent. The single source of truth for transcript content is `editor` (an in-memory Editor; edit_seq, frozen_lines, and TurnId metadata-by-LineAnchor are the canonical inputs), plus a small set of authoritative reconciliation counters/machines (turn_phase, last_seen_turns, replay_turn, reconciler, user_turn_ks — classified source-of-truth here since the schema lacks a 'reconciliation' bucket) and the tool-call maps (tool_calls/tool_call_order/tool_call_anchor_line). Everything else is either a derived cache, transient UI state, an external handle, or persistence mirrored from the AgentSlot. The dominant drift hazard is the derived-cache layer: a single structural fingerprint (`view_model_fingerprint`, 5084) gates flat_items_cache+gutter_cache via `memoize_view_model` (5125), while three other caches use independent ad-hoc invalidation keys — lines_cache keys on edit_seq, highlight_cache diffs lines internally, and block_cache/block_ranges key ONLY on frozen_line_count. The block cache's coarse key is the sharpest hazard: any frozen-content reshape that leaves the frozen line COUNT unchanged will not re-detect/re-parse blocks. The fingerprint deliberately excludes cursor/selection/theme/tool-call-content (read live inside the render closure), so a future flat-build dependency added without a matching fingerprint input would silently serve stale frames. reconcile_list (5379) is the sole mutator keeping list_state and list_item_count in lock-step. reset_for_replay (5408) is the one place that must clear every derived+reconciliation field together; an omission there leaks stale rows across a server reconnect/replay (note agent_mode is NOT reset there)._

## sketch-gpui workspace + session-ring + persistence state (main.rs, workspace.rs)

_The GUI's authoritative live state is the in-memory Workspace<WindowContent> (workspace.rs) — tabs, each rooting an n-ary Layout split tree of Windows, plus a buffer pool and three monotonic id counters. Each Agent window owns an AgentRing of AgentSlots; a slot's identity is fragmented across four coordinates that must agree: the per-ring monotonic `index` (used by the pump to find a slot), the process-wide `pending_open_token` (used to bind async server round-trips back to the right placeholder across rings whose `index` both start at 0), the `server_session_id` (the server's routing key), and `resume_id` (the ACP id retried on reboot). The main drift hazards: (1) two disk files — workspace.json (layout shadow) and acp_sessions.json (ring slots) — keyed by cwd, written best-effort at different times, that can disagree about which agent windows/sessions exist; the workspace snapshot deliberately drops live agent state (persists only a stub) and relies on the separate acp_sessions path to rehydrate, so the two can diverge. (2) The cwd key is computed inconsistently — save_workspace_state/save_agent_ring use `std::env::current_dir()` while the agent-restore path uses `process_cwd()` and persistence comparison uses raw `cwd.display()` strings (no canonicalization, unlike cwd_match_key used elsewhere), so a symlinked launch dir can fail to match its saved entry. (3) `next_index`/`active`/labels are derived from ring order and must stay consistent through close_at/close_active re-indexing and through async resolution that pushes extra slots. (4) `has_unseen_activity` is mirrored into EVERY ring in every tab by index on pump events, so a duplicated index across rings would cross-contaminate. (5) The id allocators (next_window_id/next_buffer_id/next_tab_index) must be advanced past restored ids or new windows collide with restored ones._

## sketch session-server + IPC client state

_The session server is the authoritative owner of every live ACP agent and its transcript: each ManagedSession holds the live channel, an append-only event_log (the durable source-of-truth transcript), a turn count, ownership, and pending prompts; the SessionManager keeps the sessions HashMap plus a manager-level broadcast for list changes. Per-connection state (subscribed forwarders, conn_id ownership) lives in handle_connection. The hardest drift hazard is the turn count, which exists in FOUR places that must stay reconciled: the agent's authoritative AtomicUsize (acp_channel turns), the server's ManagedSession.turns (cache of it, written only on turn-end), the replay_fence (a frozen snapshot of turns at restore time used to suppress replayed events), and the GUI's last_seen_turns. The pump thread's last_turns/synced_gen locals are a further derived layer, and channel_generation exists solely to rebaseline them after a restart resets the agent counter to 0. The second major hazard is persistence: session_server.json (the durable session snapshot) is reconciled against each session's cwd, and is deleted-on-restore so a crash mid-restore drops stale entries; restored sessions without an acp_session_id are silently skipped. The client mirrors transcript via a notification channel whose source-of-truth is server event_log (broadcast is only a wake signal), and splits requests into fire-and-forget (prompt/cancel/restart/rename) vs acked (everything else), with a shared next_id/pending/connected triplet between SessionServerClient and its off-thread SessionServerHandle._

## Per-document + editor + input-surface state (sketch-gpui main.rs, editor.rs, document.rs, workspace.rs)

_Sketch layers its text state in three tiers. (1) document.rs::Document owns the only authoritative byte store — a ropey Rope plus edit_seq (monotonic generation), modified flag, and the undo/redo stacks of O(edit) Splice deltas; it notably does NOT own the cursor/selection (those are passed in/out of every undo call). (2) editor.rs splits per-buffer substrate (EditorCore: rope+tree-sitter+frozen_lines+lockable_through_line+anchors+metadata+last_llm_line cache) from per-view UI state (EditorView: cursor, selection_anchor, extend_mode, in_insert_mode), with Editor a thin 1:1 wrapper duplicating ~70 delegating methods over both — the dual API surface is pure duplication kept for the TUI's old 1:1 shape. (3) main.rs holds the GPUI window-content states (DocState, EditState/SharedEditor, BrowserWindow, AgentState/Chatbox) plus a forest of render caches keyed on edit_seq. The dominant drift hazards are: frozen_lines / lockable_through_line / line_anchors / line_metadata / last_llm_line must all shift in exact lock-step on every insert/delete or the frozen-vs-editable classification and LLM splice point corrupt the transcript (undo sidesteps the shift machinery and so must reset_line_anchors + snapshot/restore frozen state through the Document undo entry); the type-erased LineMetadataStore (HashMap<TypeId, HashMap<LineAnchor, Box<dyn Any>>>) loses all compile-time type safety and silently returns None on a TypeId/downcast mismatch; the buffer pool (FileBuffer/FileBufferId) is now wired for the Edit path (EditState→SharedEditor→SharedCore=Rc<RefCell<EditorCore>>, GC by Rc strong-count) but the Doc and Agent paths still construct their own Document/Editor outside the pool, so the same on-disk file can be backed by two independent ropes; and the many *_cache / *_seq / *_fp fields scattered across DocState/EditState/AgentState are derived projections of (rope text via edit_seq, frozen_line_count, tool_call_order) that go stale unless every mutator bumps edit_seq and every reassignment of `blocks` calls invalidate_blocks_snapshot._

## Turn-attribution + reconciliation + pump state (sketch-gpui agent transcript / ACP channel / session server)

_The turn number k and "replaying" flags are represented redundantly across three crates and two pump paths, and most of the drift hazards come from inference rather than authoritative state. There is no single owner of "turn k": it is derived three different ways — (1) a worker-side completed-turn AtomicUsize (acp_channel.rs:355) that the protocol does not provide and that *restarts at 0* on every channel re-spawn; (2) the bin's (last_seen_turns, replay_turn) pair behind the ReplayTurns view (main.rs:4935/4947, current_turn()=last_seen+1 or replay_turn); and (3) the server's own ManagedSession.turns + replay_fence (session-server main.rs:39/65) computed by *the same* "queue empty AND turn_count climbed" inference the GUI uses. Three pumps independently re-run that inference (GUI per-session pump_session, server spawn_pump_thread, plus the server-batch path which trusts the server's TurnEnded), and each carries its own last_turns baseline that must be rebaselined on channel_generation/force-restart. The reconciler (agent_transcript.rs) is the one genuinely order-independent, unit-tested piece, but it is fed a `replaying`/`advance_boundary` bit that is computed *outside* it (!server_managed) and a separate site — submit_worksheet — bypasses the reconciler/insert_user_turn chokepoint entirely and computes turn_k = last_seen_turns+1 by hand. The dominant drift hazards: (a) AtomicUsize turn counter resetting to 0 vs. last_seen baselines on restart/resume; (b) the "turn ended = !more_pending && current_turns > last_seen" heuristic firing on a transiently-empty queue mid-stream (mitigated for replay by the explicit ReplayComplete marker but still inference for live turns); (c) replay_turn vs last_seen_turns folding (finish_replay) being the only thing that keeps live k contiguous after a resume; (d) the worksheet submit path duplicating k-derivation logic that the chatbox path routes through the reconciler._
